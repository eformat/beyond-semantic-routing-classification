Findings

  • The image alone changes nothing: arm A runs the kvcached image with the patch disabled — zero patch lines, native behaviour.
  • Elastic memory with reuse matches native caching: arm C ≈ arm A on TTFT, both ~100% prefix-hit rate on the engine counters.
  • Reuse is the strategy: the no-reuse counterfactual (arm B) loses 5.8s of TTFT per conversation (21%) and the penalty grows linearly with conversation length.
  • The noise floor works: REASONING turns escalate to the MaaS glm tier on every arm — identical timing across arms (±0.03s) normalises the measurement.
  • Open caveat: arm C's cumulative TOTAL (55.0s) is 8.9s higher than arm A's (46.1s) despite the equal-or-lower TTFT — decode-path variance over this sample or a real kvcached decode overhead; the decode-per-token metric resolves it.

How to read this

The substrate comparison holds the engine, models, hardware and prompts constant; the ONLY variable is the KV-cache substrate. Arms A and C should behave alike on cache hits (both reuse the prefix) and differ in what happens under memory pressure — kvcached's elastic blocks vs vLLM's static per-slice reservation. Arm B is the counterfactual: elastic memory WITHOUT reuse, the marginal-cost-of-switching story. REASONING turns measure the shared MaaS path — any per-arm variance there is measurement noise, the normalisation baseline for the other deltas.
