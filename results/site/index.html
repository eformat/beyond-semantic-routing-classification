Beyond semantic routing — the KV-cache substrate comparison

The path under test: every request flows client → praxis gateway → llm-d-sc classifier (gRPC) → tier splice → inference substrate — the gateway classifies each prompt (SIMPLE/MEDIUM/COMPLEX/REASONING), splices the winning tier's model into the request body, and forwards to one of the substrate arms below.

The same paired conversations replayed through four inference substrates that differ in exactly one thing: how the KV cache is managed — and specifically whether APC (automatic prefix caching: the engine detects that an incoming prompt shares a prefix with one it has already processed and reuses the cached KV blocks instead of recomputing them — the win in multi-turn, where every turn resends the conversation history) is enabled, and where the cache lives.

Arm A runs native vLLM APC (vLLM's own cache, statically reserved per MIG slice); arm B runs kvcached with APC disabled (every turn re-prefills from scratch); arm C runs kvcached with APC on (kvcached's bounded APC: reuse preserved, but the cache memory capped so it cannot starve decode); arm D runs both models on one shared slice with kvcached allocating the KV memory elastically.

Same engine (vLLM 0.30), same models (Qwen3 0.6B/8B) — arms A–C reserve 53GB of NVRAM each across two statically-partitioned MIG slices (18GB for the 0.6B + 35GB for the 8B, one replica per model). Arm D carries both models in one 71GB slice with kvcached allocating the KV memory elastically.

The classifier routes SIMPLE/MEDIUM to 0.6B and COMPLEX to 8B on every arm; REASONING turns escalate to the MaaS gateway's glm-5.3-flash — identical across arms, the built-in noise floor.

Findings

  • The elastic-sharing thesis is proven: both models on ONE 71GB slice, kvcached allocating elastically — arm D matches the statically-partitioned native setup on TTFT (20.5s vs arm A 23.0s) while serving the best Σ total (30.7s). The prefix caching works across both engines sharing the pool: arm D accrued +208128 hits on its counters. You don't need 53GB statically partitioned across two slices to keep reuse — one slice with the VMM does it.
  • The image alone changes nothing: arm A runs the kvcached image with the patch disabled — zero patch lines, native behaviour.
  • Elastic memory with reuse matches native caching: arm C ≈ arm A on TTFT, both ~100% prefix-hit rate on the engine counters.
  • Reuse is the strategy: the no-reuse counterfactual (arm B) loses 4.2s of TTFT per conversation (19%) and the penalty grows linearly with conversation length.
  • The stall rate: 1 TTFT stalls across 768 turns (~60s each, recovering) — every substrate arm hits them, transient, not substrate-specific.
  • The noise floor works: REASONING turns escalate to the MaaS glm tier on every arm — identical timing across arms (±0.03s) normalises the measurement.

How to read this

The substrate comparison holds the engine, models, hardware and prompts constant; the ONLY variable is the KV-cache substrate. Arms A, C and D should behave alike on cache hits (all reuse the prefix); what separates them is layout — A and C pair two statically-partitioned slices per arm, D carries both models on one shared slice with elastic KV. Arm B is the counterfactual: elastic memory WITHOUT reuse, the marginal-cost-of-switching story. REASONING turns measure the shared MaaS path — any per-arm variance there is measurement noise, the normalisation baseline for the other deltas.
